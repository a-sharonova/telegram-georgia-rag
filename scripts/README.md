# Деплой-скрипты и systemd-юниты

Этот каталог содержит юниты для ОДНОГО деплоя (сейчас — Грузия,
`COUNTRY=georgia`). Второй, независимый деплой (например Испания,
`COUNTRY=spain`) — отдельный процесс/чекаут со своим `.env`, своей
директорией данных и своими systemd-юнитами; см. план в
`countries/__init__.py` и корневой `CLAUDE.local.md` (приватные детали
деплоя туда и не коммитятся).

## Как добавить юниты для новой страны

Скопировать и переименовать (заменить `georgia` → `<страна>` везде — в
именах юнитов, `Description=`, путях):

- `georgia-weekly.service` / `georgia-weekly.timer`
- `georgia-daily-stats.service` / `georgia-daily-stats.timer`
- `georgia-bot.logrotate`

Также заменить в содержимом каждого файла:
- `/opt/telegram-georgia-rag` → путь нового чекаута кода;
- `/opt/telegram-georgia-data` → путь новой директории данных
  (`GEORGIA_DATA_DIR`/`GEORGIA_CHROMA_DIR` в `.env` нового деплоя должны
  указывать сюда же — имена самих переменных не переименовываются, это
  осознанный косметический долг, не блокер).

**`georgia-bot.service` в репозитории НЕТ** — он создан руками
непосредственно на сервере (см. `CLAUDE.local.md`), поэтому для новой
страны его тоже нужно написать руками по тому же образцу: отдельный
`WorkingDirectory`, отдельный `.env` с `COUNTRY=<страна>` и своим
`BOT_TOKEN`.

## Что НЕ дублируется

`notify_ban.sh`, `notify_on_failure.sh`, `fail2ban-telegram-notify.conf` —
общесерверные (уведомления о бане/краше на уровне хоста), не привязаны к
конкретной стране. Один экземпляр на сервер, даже если на нём крутится
несколько ботов.
